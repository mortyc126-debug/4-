# Куда переехать, чтобы игра открывалась без VPN

## Обход через свой домен (/sb) снят — он не работал и сломал игру

**Это главное, что нужно знать, прежде чем читать остальное.** Ниже по тексту
описан запасной путь до данных через собственный домен: `/sb/...`, которое
хостинг переписывает на `supabase.co`. Он был сделан, но **на живом сайте не
применялся ни одного дня**, а в итоге сам положил игру. Снят целиком.

Что показала проверка с телефона автора без VPN (`netcheck.html`):

| Что проверяли | Ответ |
|---|---|
| Сам сайт | HTTP 200, 332 мс |
| Данные игры (карта высот) | HTTP 200, 150 мс |
| **Сервер игры напрямую** | **HTTP 401, 613 мс — домен НЕ заблокирован** |
| **Запасной путь `/sb`** | **HTTP 404 — такого адреса на сайте нет** |

То есть блокировки Supabase на тот момент не было вовсе, а правило `/sb`
существовало только в `render.yaml`. На живом сайте оно не действует — судя по
всему, сервис на Render заведён руками, а не из этого Blueprint, и `routes`
оттуда не читаются.

Дальше сработала ловушка в самом клиенте. Он переключался на запасной путь
при первой же сетевой ошибке **и запоминал выбор на сутки**. Одной случайной
потери связи хватало, чтобы все запросы начали уходить на `/sb`, где хостинг
отдавал свою страницу 404. А 404 — это успешный ответ: промис не отвергается,
«путь непроезжий» не срабатывает, откатиться назад механизм не мог. Игра
оставалась мёртвой сутки при полностью рабочем сервере. Выглядело это как
«здания не улучшаются» и «нажимаю — ничего не происходит».

**Если возвращаться к этой идее — начинать не с кода игры, а с хостинга.**
Сперва убедиться, что правило вообще применяется: `/sb/auth/v1/health` должен
отвечать чем угодно, кроме 404, и через него должен проходить POST с
заголовками. Обе проверки уже есть в `netcheck.html`. Пока правило не
работает, клиентская половина обхода бессмысленна и опасна.


## Что показала проверка

Автор: без VPN «ни одна вкладка не открывается, даже твоя с тестом, вечная
загрузка». Отдельно проверено, что домен данных (Supabase) при этом
отвечает — см. ниже.

Это диагноз, а не симптом. Важны две детали:

* **не открывается вообще ничего**, включая `netcheck.html` — значит дело не в
  Supabase и не в библиотеке с CDN. До браузера не доезжает сама страница;
* **вечная загрузка**, а не «сайт недоступен» — почерк блокировки по имени
  хоста: пакеты не отвергаются с ошибкой, а молча выбрасываются, и браузер
  ждёт до таймаута.

Отсюда: блокируется ХОСТИНГ. Правки внутри игры этого не лечат в принципе —
код не выполняется, потому что его нечем загрузить. Лечится только сменой
точки входа.

Сделанное раньше (своя копия библиотеки Supabase вместо cdn.jsdelivr.net и
запасной путь `/sb` до данных) не пропало зря: оно понадобится ровно в тот
момент, когда сайт станет доступен, — Supabase лежит на чужом домене и может
быть закрыт отдельно от хостинга.

## Проверка сделана: Supabase доступен

Автор открыл без VPN

    https://xzuwqgpwzlmpglnuijio.supabase.co/auth/v1/health

и получил ответ:

    {"hint":"No `apikey` request header or url param was found.",
     "message":"No API key found in request"}

Это **успех, а не ошибка**. Сообщение — обычная реакция Supabase на запрос без
ключа: сервер разобрал запрос и ответил по существу. Значит соединение прошло
целиком — DNS, TCP, TLS, HTTP, — и домен данных для игрока открыт.

Итого: **блокируется только хостинг, Supabase доступен.** Из этого следует,
что подойдёт ЛЮБОЙ доступный хостинг статики — уметь проксировать он не
обязан, прокси `/sb` остаётся просто страховкой на случай, если однажды
закроют и Supabase.

## Варианты

| Куда | Плюс | Минус |
|---|---|---|
| Свой домен на нынешнем Render | час работы, ничего не переносится | помогает, только если блокируют по имени `onrender.com`, а не по адресам его CDN. Проверяется быстро и стоит попытки первой |
| Российский хостинг статики или объектное хранилище | дёшево, просто, доступность гарантирована | обновление выкатывать самому (или настроить деплой из репозитория) |
| VPS в России + nginx | полный контроль, готовый конфиг рядом | нужен сервер (от ~200 ₽/мес), сертификат, руки |

Раз проксировать больше не обязательно, второй вариант стал самым разумным по
соотношению сил и результата. Первый стоит попробовать до него — он бесплатный
и занимает час.

## Сколько весит то, что нужно раздавать

    heightmap   12 МБ     запечённый рельеф, нужен целиком
    models      341 МБ    но 269 МБ из них — models/generals, ИСХОДНИКИ
                          фигур из редактора; игре они не нужны, она берёт
                          models/marches (16 МБ, см. tools/decimate_glb.mjs)
    textures    9 МБ
    images      17 МБ
    engine/dist + vendor  350 КБ

То есть игре хватает примерно 110 МБ, из которых на первый заход игрока
реально качается заметно меньше — модели тянутся по мере надобности. При
переезде на хранилище с лимитами `models/generals` можно не выкладывать
вовсе: он лежит в репозитории как исходник, а не как ассет игры.

## Переезд на свой сервер

Сборка не нужна: `engine/dist` лежит в репозитории готовым, всё остальное —
статика.

    sudo apt install nginx certbot python3-certbot-nginx
    sudo git clone <репозиторий> /var/www/pravo
    sudo cp /var/www/pravo/deploy/nginx.conf /etc/nginx/sites-available/pravo
    sudo ln -s /etc/nginx/sites-available/pravo /etc/nginx/sites-enabled/
    # заменить ВАШ-ДОМЕН в конфиге на настоящий
    sudo certbot --nginx -d ваш-домен.ru
    sudo nginx -t && sudo systemctl reload nginx

Обновление игры после этого — `git pull` в `/var/www/pravo`.

Проверить, что всё поднялось: открыть `ваш-домен.ru/netcheck.html` **без
VPN**. Строка «запасной путь» покажет, работает ли прокси `/sb`.

## Что останется сделать в самой игре

Ничего обязательного. Адрес Supabase зашит в `index.html` одной константой
(`SUPABASE_URL`) и менять его не нужно: игра сама уходит на `/sb`, когда
прямой путь молчит.
