# Регионы + альянсовые крепости — план

Черновая проработка идеи автора (в духе Rise of Kingdoms/Total War): карта
общего мира делится на регионы, каждый регион вмещает ровно одну
альянсовую крепость, владеющий регионом альянс получает пассивный бафф,
зависящий от преобладающего рельефа региона (степь → атака конницы, горы →
защита/кузница, лес → дерево/лучники и т.д.).

Сейчас в игре **нет вообще никакой механики альянсов** — `mpMailAllianceEntries()`
в `index.html` возвращает пустой список нарочно (см. её комментарий: "в
игре пока нет ни одной механики альянсов... раздел честно пустой"), вкладка
"Альянс" — чистая заглушка на будущее. Это полностью новая система,
не доработка существующей — план ниже размечен с расчётом на это.

## Что уже сделано (этот коммит)

`generate_regions.py` — офлайн-генератор, делит настоящий рельеф игры
(`heightmap/elevation-v6.bin` + `forest.bin` + `moisture.bin`, тот же, что
грузит `engine/src/terrain.ts`) на 16 регионов:

1. 16 зёрен, выровненных по площади (релаксация Ллойда) — `preview_equal_area.png`.
2. Те же зёрна, но границы растекаются по **стоимости прохода** (Дейкстра/
   `skimage.graph.MCP_Geometric`: в гору дороже, через реку дороже) —
   `preview_total_war.png`. Автор попросил именно этот вариант: границы
   сами ложатся на реки и горные гряды, а не режут карту по прямой.
3. `regions-v1.bin` — запечённые данные, 1 байт на мировую клетку (2400×1200,
   тот же формат, что и heightmap/*.bin): 0..15 = id региона, 255 = вода/
   вне региона. **Пока никем не читается** — артефакт на будущее, когда
   дойдёт до реализации.
4. `regions_meta.json` — по каждому региону: число клеток (площадь),
   мировые координаты зерна и центроида. Пригодится и для баланса (не
   должно быть один регион в 3 раза больше остальных), и для отладки.

Число регионов (16), веса гор/рек (`MOUNTAIN_COST_K=9`, `WATER_COST=55`) —
не финальные, это стартовая точка, которую автор уже одобрил визуально по
двум присланным скриншотам. Крутится одной правкой констант в шапке
скрипта и перезапуском.

## Открытые вопросы (нужно решение автора до кода)

- **Тип баффа на регион** — считать автоматически из `forest`/`moisture`/
  высоты региона (например: медиана высоты > X → "горный", доля леса > Y →
  "лесной", иначе "степной"/"равнинный") или расставить вручную по каждому
  из 16 — авто честнее и не требует поддержки при перегенерации, ручное
  даёт более осмысленный лор ("вот тут древний рудник").
- **Как регион переходит к альянсу** — захват крепости-цели внутри региона
  (осада, как у обычных городов/точек) или что-то вроде текущих "точек
  сбора" (`nodes`), где решает не разовый бой, а удержание? Смежный вопрос:
  что происходит с регионом, если владеющий альянс распался или все его
  участники вышли.
- **Масштаб баффа** — фиксированный (+5% как в примере автора) или растёт
  от числа регионов/уровня крепости? Складывается ли с личными баффами
  игрока (`bonuses()` в index.html уже считает атаку/защиту от расы,
  снаряжения, талантов, погоды — региональный бафф встанет туда же
  отдельным слагаемым).
- **Что видит игрок БЕЗ альянса** — сейчас у любого одиночного игрока в
  этом мире альянса нет и не предвидится (сам концепт только заводится).
  Бафф региона логично должен действовать на ВСЕХ членов владеющего
  альянса, а не только на того, кто физически в городе внутри региона —
  иначе это не государство, а просто локальный бонус клетки.

## Наметка по шагам реализации (когда решения выше приняты)

1. **Схема БД** (`supabase/migrations/000N_alliances.sql`):
   - `alliances` (id, name, tag, created_at, leader_player_id)
   - `alliance_members` (alliance_id, player_id, role, joined_at)
   - `regions` (id 1..16, resource_kind, buff_json — статика, можно просто
     засеять из `regions_meta.json` один раз, руками или скриптом-миграцией)
   - `region_ownership` (region_id, alliance_id NULL, captured_at) — NULL =
     ничей, регион свободен
   - Разметка "какому региону принадлежит клетка" — либо гонять
     `regions-v1.bin` на сервер и смотреть по координатам игрока, либо (проще
     для Postgres) один раз посчитать `region_id` для каждой существующей
     позиции города/точки/лагеря и держать как обычную колонку.
2. **UI вкладки "Альянс"** в `mpMailAllianceEntries()`/соседних функциях
   (`index.html`) — сейчас там честная заглушка, там же и заводить: список/
   создание альянса, список участников, какие регионы держит.
3. **Карта регионов поверх мира** — 3D (`engine/src/`) или 2D-оверлей
   (`index.html`, тот же слой, где сейчас рисуются метки точек/лагерей):
   подсветка границ + подпись владельца, тот же принцип, что и текущие
   ambient-подписи в `main.ts`.
4. **Захват региона** — новая supabase function (по образцу `mp-attack`/
   `mp-raid`) или расширение существующей осадной механики на "крепость
   региона" как отдельный тип цели.
5. **Применение баффа** — в `bonuses()` (index.html) и в её зеркале на
   сервере (там, где считается бой, `mp-tick`/`runPvpBattleRounds` и т.д.):
   подтянуть regional buff владеющего игроком альянса как дополнительное
   слагаемое, тем же способом, что уже используются бонусы расы/снаряжения.

## Как перегенерировать превью

```bash
pip install numpy pillow scipy scikit-image   # только для этого скрипта, не для игры
python3 worldgen/regions/generate_regions.py
```

Параметры — константы в шапке `generate_regions.py` (`N_REGIONS`, `SEED`,
`MOUNTAIN_COST_K`, `WATER_COST`, `DOWNSAMPLE`). При смене `N_REGIONS`
переразметка полностью новая — старые `region_id` в БД (если к тому
моменту уже будут данные) не переживут перегенерацию один в один, так что
после фиксации числа регионов трогать `N_REGIONS` — уже осторожно, не
вслепую.
